## 1. BUGS (wrong behavior, crashes, silent data loss)

- **`build_dataiku_notebook.py` `MAPPING_CELL` — cross-run/foreign-doc mixing (the exact hazard you flagged).** The mapping loop iterates `for _key in sorted(os.listdir(OUT_DIR))` and maps/uploads any dir containing `fields_codegen_<tag>.csv`. `FETCH_CELL` only `rmtree`s doc dirs for **this run's** `PDFS`; a document processed by an earlier session (same `tag`) that the current `DOC_FILTER`/`MAX_DOCS` excludes survives in `OUT_DIR`, gets re-mapped, and is uploaded under this run's `runs/<RUN_ID>/`. It also folds those foreign docs into `_map_events`, so the run's error report gets `by_doc` rows for documents not in this run. The `UPLOAD_CELL` correctly scopes to `_run_keys`; the mapping cell must do the same. Fix: iterate `sorted({doc_key(_p) for _p in PDFS})` (or intersect `os.listdir` with `_run_keys`).

- **`build_dataiku_notebook.py` `UPLOAD_CELL` — run-root files uploaded unconditionally.** The scoping guard `if '/' in _rel and _top not in _run_keys: continue` only filters files **inside** doc dirs. Any file at `OUT_DIR` root with no `/` is always uploaded — including stale root artifacts from a previous session, notably a different-`tag` `induction_summary_<othertag>.json` / `error_events_<othertag>.csv` / `run_info_<othertag>.json`. Those get copied into this run's `runs/<RUN_ID>/`, mixing another run's summary/report into this one. Fix: at root, upload only the known current-`tag` artifact names (`induction_summary_<tag>.json`, `run_info_<tag>.json`, `error_events_<tag>.csv`, `error_summary_<tag>.json`).

- **`run_cli_induction.py` `timed_call` — JSONL write swallow is too narrow to honor "never fail a run."** The append is wrapped in `except OSError`. Writing with `encoding="utf-8"` a reply that contains a lone surrogate (possible from the Dataiku `call_mesh` transport, which returns `resp.text` verbatim — unlike `call_cli`, which uses `errors="replace"`) raises `UnicodeEncodeError`, which is **not** an `OSError`. It propagates out of the `finally` and fails the run — violating the hard constraint. Fix: broaden to `except Exception:` for the JSONL append (the `open(...,"w").close()` truncation guard has the same narrowness but only sees path errors, so it's fine).

- **`cost_report.py` `make_tokenizer` — tiktoken guard only catches `ImportError`.** `tiktoken.get_encoding("o200k_base")` can raise on first use when the encoding blob must be fetched and the host is offline (not an `ImportError`). That escapes the `try` and crashes the report instead of falling back to `chars/4`. Fix: `except Exception:` (or catch the download/`ValueError` path explicitly).

## 2. LOGICAL FLOW (ordering, rerun-safety, cross-cell dependencies)

- **`MAPPING_CELL` error-report scoping is internally inconsistent.** `run_report.collect_run_events(OUT_DIR, tag, summary)` is scoped to this run's `summary`, but `_map_events` is built from the `os.listdir` loop (all dirs). After the `+`, `write_reports` mixes this-run trail events with possibly-foreign mapping events. Same root cause as Bug #1; fixing the loop scope fixes this too.

- **Cell variable ordering is otherwise sound**, but note the coupling: `RUN_ID`, `tag`, `summary` are all minted in `INDUCTION_CELL` and consumed by `UPLOAD_CELL` and `MAPPING_CELL`. Rerunning only `INDUCTION_CELL` remints `RUN_ID`; you must then rerun upload/mapping. Rerunning `FETCH_CELL` (which wipes doc dirs) without rerunning `STAGE0_CELL` leaves no `clusters.json`, so `INDUCTION_CELL` records every doc as `skipped_missing_stage0`. Both are top-to-bottom-safe but partial-rerun-fragile — worth a one-line comment, not a code change.

- **`run_report.events_for_doc` — generate/audit transport failures produce two events at different severities.** A generate `transport_error` (→ `needs_manual_template`) yields BLOCKING `transport_error` (from the cycle) **and** FATAL `no_version_passed_gates` (from status). Likewise an audit error yields BLOCKING `transport_error` **and** QUALITY `never_page_verified` (`ok_unaudited`). This looks intended (call-site vs doc-outcome), but it means `by_severity` counts one underlying failure twice; confirm that's the desired semantics before publishing the counts.

## 3. CONSISTENCY (docs/outputs-guide vs actual artifacts; CLI vs notebook parity)

- **`run_report.events_for_doc` — rejected coverage extensions inflate `gates`.** The `extension_rejected` trail entry (written in `induce_document`) carries `"problems": verdict2["problems"]`, which can be non-empty (extension crashed/failed gates). `events_for_doc` iterates `c.get("problems")` for that confirm cycle and emits BLOCKING `gate_*` events under stage `gates`, sharing the **base version's** `version` number. So a shadow extension attempt is indistinguishable from a real version's gate failure and adds to gate-failure counts (on top of the `confirm_extension_rejected` QUALITY event). If that's not intended, gate them on `c.get("kind") != "confirm"`.

- **`_PROBLEM_CODES` vs today's strings: OK.** `"Program failed to run:"`, `"The program extracted ZERO records"`, `"Only "` (for "Only N records from…"), `"Records carry no valid 1-based"` all match by `startswith`, and no prefix shadows another. I could **not** verify `_WARNING_CODES` against `induction.gate_warnings` (module not in the review set) — the six substrings must be re-checked against the live warning strings; any drift silently degrades to `warn_other` (safe direction, but confirm).

- **Outputs-guide vs produced artifacts: consistent**, with the implicit caveat that `timings_<tag>.json` / `llm_calls_<tag>.jsonl` / `codegen_trail` / `generated_extractor` / `fields_codegen` are **not** produced for `skipped_*` or `error` docs (finalize/`induce_document` never run). The guide's per-doc table reads as "always present"; consider noting these are absent for non-processed docs.

- **CLI vs notebook parity: fine.** Notebook uses unprefixed report names; CLI uses `cli_` (`run_report.write_reports(prefix=...)`). `cost_report.py` keys off `<tag>` only and works against both `out/` and a downloaded `runs/<RUN_ID>/` tree (root files are `os.path.isdir`-skipped). Timings/by-kind math checks out: audit reprompt logs a second `audit` entry (no double count vs a single version), `sandbox_validate_s` is tracked separately from `llm_s`, and `export_s`/`stage0_s` are reported as components of `total_s` without being summed into `llm_s`.

## 4. EDGE CASES

- **`cost_report.doc_calls` — no guard on `json.loads(line)`.** A run killed mid-append leaves a truncated final JSONL line; `cost_report` crashes on it, whereas `run_report.collect_run_events` guards trail parsing (`except ValueError → corrupt_trail`). Add a per-line `try/except` (skip or warn) for parity.

- **`RUN_ID` second-granularity collision.** `INDUCTION_CELL` mints `RUN_ID = strftime('%Y%m%d-%H%M%S') + '_' + tag`. Two runs launched in the same second with the same model produce the same prefix and overwrite. Low risk; add sub-second or a short random suffix if reruns can be rapid.

- **Failed transport calls still bill input tokens.** `cost_report.doc_calls` sets `has_text` from `prompt is not None`; a failed call has `prompt` set and `reply=None`, so its input tokens count toward cost (output 0). Defensible, but call it out in the report if "cost" is meant to reflect only successful calls.

- **Handled well:** empty run (`PDFS=[]` → empty summary, empty event CSV with header, upload emits only root files, `cost_report` exits cleanly); all-skipped run (one FATAL `stage0` event per doc via status branch, no trail needed); mid-batch transport failure (per-doc `try/except` in `induce_document`'s callers keeps the batch alive; failed call logged with `error`); non-ASCII (`ensure_ascii=False` + utf-8 throughout, `detail[:300]` slices by codepoint). Huge prompts: JSONL is unbounded by design (fine), but `cost_report` loads each line whole into memory — acceptable, noted only for pathological sizes.

Highest-priority fixes: the `MAPPING_CELL` scope (Bug #1) and `UPLOAD_CELL` root-file leak (Bug #2), since both directly break the "runs never mix" guarantee; then the `timed_call` `except OSError` widening (Bug #3), since it can fail a paid run.
