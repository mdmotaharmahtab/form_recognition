 Review of the pasted pipeline source, structured per the charter. TLDR: stage-0 clustering is genuinely word-blind except for one Latin-script assumption in `_charclass`, but three defects undermine the loop's core claim on exactly the documents it targets — cross-page dedup makes the grounded audit report phantom misses on any repetitive form book, the `records < 5` hard gate permanently rejects legitimately tiny documents, and unvalidated page numbers from generated programs can inflate coverage or kill the audit. The sandbox blocks some legitimate programs while stopping no determined escape, and its threat-model note ignores that PDF text is attacker-controlled input to the code-writing LLM.

### 1. Hardcoding & corpus priors

- **[blocker]** `induction.gate_problems` — `m["records"] < 5` encodes "a CRF yields ≥5 distinct records", measured **post-dedup**. A 1–2 page form, or a book that is one repeated 4-field form on 300 pages (dedups to 4), hard-fails every version → `needs_manual_template` for a correct program. Fix: only `records == 0` is unconditional; apply the `< 5` floor only when `pages_total` is large, else demote to warning.
- **[should-fix]** `generic_profile._charclass` — `" " not in t and (digits > 0 or t.upper() == t)` → `"code"`. CJK/Thai (no word spaces) and caseless scripts (CJK, Arabic, Hebrew) classify **every** text line as `code`; the word/prose/code dimension of the token — one of five — collapses document-wide for those languages. Latin single-word all-caps labels ("AGE", "SEVERITY") also become `code`. Fix: detect caseless text via `t.upper() == t.lower()` and classify by length/digit-content instead of spaces and case.
- **[should-fix]** `induction.score` — `CODE_SHAPE = ^[A-Z][A-Z0-9_]{1,39}$` inside `labels_look_human_pct` is an ASCII-caps prior: documents with caps-styled single-word labels get pushed under the 60% warning and into pointless revision rounds. Fix: require a digit/underscore in the code-shape exclusion, or drop the exclusion from this metric.
- **[should-fix]** `stage0_cluster.run` — `text_layer_pct >= 20` → status `ok`: a 79%-scanned document proceeds, its scanned pages silently unreachable, and nothing downstream (summary rows in `finalize_document`, notebook summary) carries `text_layer_pct`. Fix: keep 20 as the skip floor but propagate the percentage / a `partial_text` flag into the summary.
- **[should-fix]** `common.doc_key` — non-ASCII stems sanitize to `_`-runs; when the result is ≤70 chars no hash is appended, so distinct non-Latin filenames collide and the batch dies on the collision assert (`run_cli_induction.main`, `FETCH_CELL`) with "rename the files". Fix: append the hash whenever sanitization changed the stem.
- **[should-fix]** `common.build_page_lines` — bold via font-**name** substring `"bold"`: many non-Latin/embedded fonts don't carry it (e.g. CJK weight names like "W6"). Self-consistent (dumps and runtime agree) but degrades `.bold` and the profile's `B` dimension as generic signals. Fix: OR-in the PyMuPDF span flags bold bit.
- **[acceptable-with-comment]** `generic_profile` meta-constants — `THETA_GRID` endpoints, `PLATEAU_RI=0.97`, damping exponent 3, `X_BINS=6`, `_size_rel` 0.9/1.15. Stability selection only searches inside [0.30, 0.60]; a document whose plateau lies outside gets endpoint behavior. The written defense plus `generalization_audit.py` is adequate; keep that audit runnable in CI.
- **[acceptable-with-comment]** `pick_representatives` / `common.cluster_pages` — pages 0 and 1 are always representatives ("title/TOC at front" convention). Generic-document prior, worst case two wasted slots.
- **[acceptable-with-comment]** `common.BRACKET_LINE` / `INT_ONLY` (v1 fingerprint) — annotation-convention prior, reference-only; verify nothing production-side calls `common.cluster_pages`.
- **[acceptable-with-comment]** `replay.py` engine defaults — `oid_header="Include"`, `name_header="Name"` / `"Export Name"`, x-coordinate defaults 320/460/480/108, `[A-Za-z]` checks in `find_form_name`, `_parse_content_page`, `extract_line_pattern`. Corpus fixtures, documented as not-to-ship; the production path imports only `FieldRec`/`ReplayResult` from this module, which keeps the priors out.
- **[acceptable-with-comment]** `eval_form_field.norm` and the notebook `MAPPING_CELL` `_norm` — strip everything non-ASCII. Documented for eval; note the mapping cell will print ~0% mapped on non-Latin documents while looking like a real measurement.
- **[acceptable-with-comment]** `run_cli_induction.DEFAULT_DOCS` — author-corpus filenames, harness `main` only.
- **Prompt text**: `CODEGEN_PROMPT`, `AUDIT_PROMPT_TEMPLATE`, `COVERAGE_CONFIRM_TEMPLATE` carry no vendor/layout priors; English option examples are explicitly marked as examples and "may be in any language" is present. Residual: the prompt gives no hint that y-then-x line order is anti-reading-order for RTL scripts, and nothing about vertical CJK text (see §4).

### 2. Bugs

- `replay.ReplayResult.dedup` + `codegen.run_extractor` — dedup key omits `page`, so all cross-page repeats collapse to first occurrence. Consequences: (a) the audit (`pick_audit_pages`, `build_audit_prompt`) pairs page dumps with **post-dedup** records, so repeated fields on an audited page show as not-extracted → phantom `missed` findings → zero-issue convergence is near-impossible on repetitive form books, i.e. the core document class; the loop burns full budget and lands on `ok_audit_issues`. (b) `metrics["records"]` and the revision-prompt sample shown to the model are post-dedup, contradicting what its program actually returned. (c) It contradicts `CODEGEN_PROMPT`'s own "beyond what the document itself repeats". The authors have already collided with this: `SELFTEST_PROGRAM` appends a `(pN)` suffix specifically to defeat dedup. Fix: dedup on `(form, field, page)`, or keep raw records for audit/metrics and dedup only at CSV export.
- `codegen.run_extractor` — no page-range validation. Records with `page > n_pages` (or huge) inflate `covered_pages`/`pages_with_fields` (poisoning the `version_score` tie-break, the `improves` coverage guard, and `pages_covered_pct` which can exceed 100), and `build_audit_prompt`'s `doc[p - 1]` raises → `stop="audit_error"` → document downgraded to `ok_unaudited`. Fix: drop or zero pages outside `1..n_pages` when parsing the child payload.
- `run_cli_induction.induce_document` confirm block — an adopted extension overwrites `reply`/`verdict` **before** the cycle's trail entry is appended, so the original version's gate metrics never enter the trail and it is never scored for best; an extension that is worse on warnings/audit displaces it unexamined (adoption only checks records/coverage monotonicity). Fix: score and record the original version first, then treat the extension as the next version.
- `codegen.validate_generated` — one `try` spans run + gates + feedback building; failures **after** a successful run (missing/corrupt `clusters.json`, `fitz.open` in `build_cluster_feedback`) are reported as "Program failed to run: …", misdirecting the revision at a working program. Fix: separate try scopes.
- `codegen.validate_generated` — `if weak: cluster_feedback = build_cluster_feedback(...)`: that builder returns `""` when every candidate page of the weak clusters was already shown (small clusters containing pages 0/1 + their reps), and the `build_uncovered_feedback` fallback is then skipped → real holes reported as none, confirm round suppressed. Fix: fall through to the uncovered builder when the cluster builder returns empty.
- `sandbox_runner.main` — `json.dumps(payload)` sits outside the `try`; an unserializable `page` value (bytes, object) kills the child with exit 1 and the parent reports "extractor process died" instead of the structured traceback. Fix: coerce `page` to int-or-None in the child, or move `dumps` inside with an error fallback.
- `stage0_cluster.run` — `doc.close()` not in `finally`; an exception mid-run leaks the handle, and on Windows the staged PDF stays locked against re-runs/overwrites. Minor.
- `generic_profile.page_profile` — `page_height` parameter is dead.
- State leaks across documents/attempts: checked (`induce_document` locals, fresh child process per run, notebook pop-and-import, stale-output deletion order in `stage0_cluster.run`) — none found.

### 3. Logical flow

- Plateau granularity: `version_score` for any hard failure is `(1, inf, 0, 0)` regardless of failure kind, so two consecutive crashes — or a crash followed by a zero-record run — tie exactly and trigger `stop="plateau"` at version 2 of 5, even when v2 fixed v1's crash and the revision was converging. Fix: never plateau between hard-failed versions while budget remains (or fold records/error identity into the comparison).
- Coverage blind zone: the audit samples only **covered** pages (`pick_audit_pages` draws from record pages), `weak_clusters` needs `n_pages >= 4` and `coverage < 30%`, and `build_uncovered_feedback` needs ≥40% of pages uncovered. A program missing ~30–39% of the document spread over ≤3-page clusters, or covering every cluster at exactly ≥30%, gets no confirm round, no feedback, and no audit exposure of the holes → exported as `ok`. Fix: reserve 1–2 audit slots for uncovered pages and couple/lower the two thresholds.
- `CONFIRM_NO_FIELDS` is accepted at face value and never re-examined (`confirm_pending` flips once; the audit never visits uncovered pages), so a wrong confirmation is final. Cheapest mitigation: include one confirmed-field-free page in the audit sample.
- Fixed audit sample: `audited_pages` freezes on v1's coverage, so layouts only later versions reach are never audited; convergence then certifies a possibly small slice of final coverage. Also, only the zero-issue case guards against pages omitted from the reply — a nonzero count over a partial reply is trusted, making cross-version counts incomparable in the direction that selects best.
- One malformed audit reply (`parse_audit_reply` ValueError) or transport hiccup → `stop="audit_error"` ends the document; the CLI transport has no retry and `call_mesh` retries transport failures, not bad JSON. One reprompt attempt before stopping is cheap.
- `CODE_REVISION_TEMPLATE` / `COVERAGE_CONFIRM_TEMPLATE` — `verdict["source"][:6000]` truncates **silently**; the model is told to extend a program whose tail it cannot see, a direct cause of rewrite regressions. Add a truncation marker at minimum; realistically raise the cap (6–12 KB programs are routine).

### 4. Edge cases vs generality

- RTL/CJK: beyond `_charclass` (§1), `build_page_lines` sorts x-ascending and the prompt's multi-column note assumes LTR; vertical CJK text yields line bboxes for which y-then-x ordering is arbitrary. The rep dumps remain self-consistent, but induction quality degrades with no warning to the model — one prompt sentence would cover it.
- Tiny documents: blocked by the `records < 5` gate (§1); otherwise handled (`_rand_index` returns 1.0 for n<2; theta selection degrades gracefully).
- Huge fragmenting documents: `select_theta` runs 7 clustering passes; when every page is unique, leader assignment plus the k² centroid merge approach O(n²) weighted-Jaccard calls per pass — minutes at 1000 pages, contradicting the "milliseconds each" docstring claim. Bounded, but the claim is wrong. Reps then cover ~12/1000 pages and correctness rides entirely on the ≥40% fallback (§3).
- Dense pages: `load_rep_pages` (3600 chars) and `_dump_lines_text` (3200 chars) cut page bottoms from induction, feedback **and** audit. Fields below the fold are systematically invisible, and the auditor — told to judge "strictly against what is printed" — will emit phantom `false` entries for records from the truncated region. Raise the audit cap or instruct the auditor to skip past-truncation records.
- Scanned/encrypted/zero-page: handled and skipped loudly; a zero-page PDF gets status `no_text_layer` (mislabel nit). Mixed scanned ≥20% text is the real gap (§1).
- Degenerate clustering: all-pages-one-cluster is fine (2 reps + pages 0/1); every-page-unique relies on `build_uncovered_feedback` (§3).
- Generators: materialized in `sandbox_runner.main` — covered.
- Empty pages: empty profiles cluster together, but `pick_representatives`' `is_blank` only **deprioritizes** — a blank cluster can still consume a rep slot after content clusters, injecting an empty page block into the prompt. Exclude blank clusters from rep slots outright.
- Unicode: child→parent JSON is `ensure_ascii` (safe), CSVs UTF-8. Residual: `doc_key` collisions (§1); white/invisible text counts as content and as `non_black`, producing junk tokens and potential phantom fields on pages with hidden text layers.

### 5. Sandbox & safety

- Escapes: trivial — `().__class__.__base__.__subclasses__()` walks to `os._wrap_close.__init__.__globals__`; `getattr`/`setattr`/`type`/`__build_class__` are all exposed and exec restricts no attribute access. This is documented as a non-boundary, but the justification ("the author is our own induction LLM") ignores that the LLM's *input is attacker-controlled PDF text*: a hostile document can prompt-inject the codegen round, and the emitted program runs with full user privileges and network in the child. Process isolation is not privilege or network isolation. Fix at deployment level (unprivileged/no-network child where available) or state the accepted risk accurately in `sandbox_runner`'s docstring.
- Resource abuse: no cap on child records/stdout — a terminating-but-runaway program can emit gigabytes; the parent `json.loads` then blows up the notebook kernel, the exact failure the process boundary exists to prevent. Cap serialized size or record count in the child. `RLIMIT_AS` Linux-only is documented; `run_extractor`'s kill+reap on timeout is correct; no thread timeouts exist to leak.
- Legitimate-program blockers: `_SAFE_BUILTIN_NAMES` lacks `locals`, `globals`, `bytearray`, `memoryview`, `complex`, `delattr`, `dir`, `bin`/`hex`/`oct`/`ascii`, `NotImplemented`, `BaseException`, `MemoryError`, `RecursionError`, `GeneratorExit`, `StopAsyncIteration`, `UnicodeDecodeError`/`UnicodeEncodeError` — catching any of these by name NameErrors an otherwise-valid program. `from collections.abc import Iterable` breaks: `_restricted_import` returns the root package for dotted names, so `IMPORT_FROM` fails unless the submodule happens to be pre-loaded. Fix: extend the safe list; delegate dotted imports of allowed roots to the real `__import__`.

### 6. Consistency

- `subagent_bridge.cmd_validate_code` writes a revision prompt on warnings alone; production treats warnings as never-blocking and revises via audit findings. Its NOTE documents the missing confirm/audit rounds but not this warnings-semantics divergence — programs tuned through the bridge face different acceptance pressure than production.
- `run_cli_induction.main` requires `codegen_prompt.txt` pre-written by `subagent_bridge.cmd_prompts_code` (unguarded `open` — FileNotFoundError kills the whole batch) and has no per-document try/except; the notebook `INDUCTION_CELL` writes the prompt itself and wraps per-doc. The shared-controller claim holds; driver robustness does not.
- `stage0_cluster` docstring: "These representatives are the ONLY thing the code-induction step may look at" — false for the loop, which ships weak-cluster pages, uncovered pages, and audit pages to the model. Stale claim.
- `run_cli_induction` docstring: "confirm cycles share the version number of the cycle they ran in" vs code, where an adopted extension gets `versions += 1` and its own number (see the §2 trail bug).
- `UPLOAD_CELL` walks all of `OUT_DIR`, re-uploading artifacts of documents from earlier sessions that the current `DOC_FILTER` excludes — contradicting `FETCH_CELL`'s warm-work-dir guarantee. Restrict the walk to the current run's doc keys plus the summary file.
- `call_cli` docstring: "there is nothing for it to read - the blind-test property is preserved" — overstated: `--trust` print-mode agents retain tool access to absolute paths outside the empty cwd (repo, rep dumps, ground truth). The blind-test validation of the production claim is weaker than documented.
